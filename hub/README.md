# Mira hub

Receives events from each agent source, keeps the live picture of every session, tells each session's story on demand, and answers Claude Code permission prompts while Mira is open in a browser. It runs on this machine only, at `http://127.0.0.1:4711`.

## Run it

```bash
npm start        # in this terminal; or npm run dev, which restarts when the code changes
```

To keep it running without a terminal (decision 34):

```bash
npm run hub:background   # start it in the background, logging to ~/.mira/hub.log
npm run hub:status       # is it running, and does it start at login?
npm run hub:restart      # after pulling changes; terminals carry on
npm run hub:stop         # stops the hub and ends any terminals
npm run hub:login        # start it at login (Windows); undo with npm run hub:login-off
npm run update           # take Mira's update by hand; a hub in the background restarts
```

**Updates** (decision 60). Mira updates itself from the repo you cloned it from. The hub checks a minute after it starts and every six hours whether the branch it runs has new commits upstream, with `git fetch`, and when it has, an "Update ▸" button at the top right opens Settings on what's new. "Update and restart" fast-forwards the copy, runs `npm install` if `package-lock.json` changed, and restarts the hub; in the app, the app closes and opens again, and in a browser the page reloads once the hub is back. Your terminals keep running, unless the packages changed, which ends them first, since they hold the packages' native code; their conversations are kept, ready to resume. Mira only ever updates a copy with no changes or commits of its own, on a branch that tracks an upstream branch: anything else is left for you to pull, and Settings says why. If the new packages won't install, it goes back to where it was. The update runs in a process of its own, [src/updater.ts](src/updater.ts), which logs to `~/.mira/update.log`. `npm run update` does the same by hand, and restarts a hub running in the background; restart one running in a terminal yourself.

Then open `http://127.0.0.1:4711`. It's one page (decision 31): the island fills the window, the board runs down the left, and a session's story opens on the right.

**As an app** (decision 43). `npm run app` opens Mira in a window of its own instead of a browser tab, starting the hub in the background first if it isn't running; closing the window leaves the hub running. Right-click its taskbar button and choose "Pin to taskbar", and the pinned button opens it straight away, under Mira's name and icon. Only Mira's page shows in it: web links open in your browser, and VS Code links in VS Code. F5 reloads, F11 is full screen, F12 opens the developer tools, and Ctrl with plus, minus or 0 zooms. Its taskbar button wears a red badge counting the sessions calling for you that you haven't read, and flashes when one needs you, fails or finishes a long turn, unless Settings say not to (decisions 55 and 59). It keeps its size and place between runs, and needs Node 24 on the PATH to start the hub. Its icon and the page's favicon are a mirling, drawn from its pixel map in [web/sky/mirling.ts](web/sky/mirling.ts) by `npm run icons`.

- **The island** has a section per project, in the order projects first appeared, with streams between neighbouring sections, bridges where their gates meet, and waterfalls off the front edge (decision 42), and a mirling per session (decision 28). Each mirling has a name of its own on a tag over its head, which the board and the story show too; pointing at a mirling shows its name and its task, the session's name (decision 48). Mirlings act out what their session is doing (decision 41): they read with a book at the library, hammer at the workshop for edits, work a console there for other commands, and walk about with a thought bubble between tools. When a turn ends with work the session started still running in the background, such as a script or a subagent, they wait at the workshop's console with an hourglass, and the board says "Waiting on a command" instead of "Your turn"; nothing calls for you until that work reports back and the session's turn really ends. A server left running from an earlier turn doesn't count, so a later turn still ends as yours (decision 56). When it's your turn they play on the swings, down the slide or on a rubber ring in the pond, with a speech bubble. They raise a beacon when they need you, smoke when they fail, and go home when they end. Helpers follow them while subagents run. Each project's workshop grows with its commits in the last 30 days, and its library with the commits that changed docs; new commits float up from the workshop, and pointing at a building shows its count (decision 35). Drag to move; scroll or use the buttons to zoom.
- **Day, night and the seasons** (decision 62). The island follows your clock: the sun rises and sets with the time of year, the island turns warm at the end of the day, rosy at dusk and blue at night, lamps, campfires and the windows of lived-in houses glow, and more stars come out. At ten, mirlings waiting for you go home and sleep by their door, z's rising, until half past six or your reply; a mirling still working stays up. The seasons follow your calendar, as they fall in the north: blossom in spring, orange leaves in autumn, snow and snowmen in winter, with petals, leaves or snow drifting down, and jack-o'-lanterns by the houses for Halloween. Mira, the star the island is named after, sits in the top corner of the sky, brightening and fading every 332 days as the real star does, though not in step with it; point at it to see how it's going. Untick "Night and the seasons follow the clock" in Settings and it's always a summer's day. To try another time, add `?sky=2026-12-24T22:00` to the page's address.
- **Wildlife** (decision 63). Gulls cross the island now and then by day, butterflies flit about flowers, flower beds, sunflowers and shrubs in spring and summer, goldfish leap out of the streams and ponds, clouds drift beneath the island, smoke rises from campfires, and fireflies come out on summer nights. None of it stands for any work, and none of it moves for someone who's asked their system for less motion.
- **Celebrations** (decision 64), each for something that really happened. When a session's turn ends after it worked, its mirling hops twice in a puff of confetti and carries a crate home before it goes to play. Each new commit sends a firework up from its project's workshop, up to three at once, and commits that change docs a puff of confetti over the library. A workshop or library that goes up a level gets scaffolding, grows into its new size and throws confetti.
- **Playing with mirlings** (decision 65). Press on a mirling and drag to pick it up: it dangles from the pointer, kicking its legs, and when you let go it drops onto the nearest tile it can stand on, in a puff of dust, and carries on with what it was doing from there, walking back if it has to. A plain click still opens its story, and clicking the mirling whose story is open pets it: a heart, and a hop if it's standing still. With a story open, "Follow" by Build keeps the camera on its mirling as it goes about; moving the camera yourself, or picking a mirling up, stops it. Tick "Tour the island while I'm away" in Settings, and after three minutes without your touching Mira, with no story open, the camera drifts from one mirling to the next, one calling for you first, then one at work, a stop every 20 seconds, until you move the mouse or press a key, when it goes back to where it was.
- **Build mode.** "Build" at the bottom right opens a palette where the story would be. Pick a plant, a decoration, something for the water, a play piece, or path, grass, flowers or pond, then click a tile anywhere on the island: a project's own ground, its shore, the coast or a stream bank. Boats and lily pads go on streams and ponds; bridges stay as they are (decision 44). Pond digs water out of land, and path, grass or flowers on a pond fill it in; streams stay. Swings, slides and trampolines go up anywhere free, as many as you like, and mirlings waiting for you play on them (decision 49). Move picks up a building and puts it on a free tile of its own ground, or a play piece and puts it on a free tile nearby; Restyle gives a house the next style; Remove takes away a plant, a decoration, a tree or a play piece. Buildings that stand for real work are never added or removed. A change that would leave a building or a play piece with no way in is refused. Each change is kept by the hub as it's made and shows in every open page; Undo takes changes back, and Done or Escape leaves (decision 39).
- **Settings** at the top right switch each way Mira calls for you on or off on its own: desktop notifications, the app's pop-up and the flash of its taskbar button, remembered in that browser or app (decision 59). The glow on the board and the red badge stay either way. Settings also show where Mira's own copy stands, and its update when there is one.
- **What Mira costs** (decision 61). Settings show Mira's share of the machine's CPU, as Task Manager counts it, and its memory, while they're open: the hub, the terminal host and, in the app, the window, the graphics card's share and the app itself. A browser can't say what its tab costs, so there the page shows how many frames the island drew and how long each took; the browser's task manager (Shift+Esc) has the rest. Claude Code's own sessions, in Mira's terminals or anywhere else, aren't counted. The island is drawn at most 60 times a second, however fast the screen refreshes, and 20 times while Mira isn't in front, unless you untick "Slow it down while Mira isn't in front".
- **Notifications.** Tick "Desktop notifications" in Settings, and a notification tells you when a session needs you, fails, or finishes a turn that took over 20 seconds, while Mira isn't in front of you. Click one to bring Mira forward on that session (decision 45). A browser asks once for permission; the app has it already, and keeps a Mira shortcut in the Start menu so Windows shows its notifications under Mira's name and icon. The app also puts up a pop-up of its own in the middle of the screen it's on, unless you switch it off in Settings, since Windows keeps its notifications in the far corner, which is easy to miss on a wide screen (decision 55). It shows while Mira is in front of you too, say while you're working in its terminal, for every session but the one you have open. Showing it never takes the keyboard from what you're typing in. Each session gets a card, which stays until you deal with it; the newest is open and the others wait as a line each, a click away. A finished turn's card shows the session's last reply, with a box to answer it and quick replies, "Go ahead", "Commit" and "Commit and push" unless `quickReplies` says otherwise: Enter sends, Shift+Enter starts a new line. A permission prompt's card shows what it wants to run, with Allow and Deny while Mira can still answer it. Your reply goes as the story's box sends it, below, and the card says which way: typed into Mira's terminal as yours, or from Mira, in which case "Paste in VS Code" copies it and opens the conversation for you to paste and send yourself (decision 57). Open in Mira brings Mira forward on the session, Open in VS Code opens the conversation in its VS Code window as Continue in VS Code does, and × closes the card; each marks the session read. The reply is read from the transcript for the card and never kept. Windows snap tools such as FancyZones leave it where it is.
- **Two sessions, one file** (decision 58). When two live sessions have both edited the same file in the last hour, both rows say which file with a ⚡, both mirlings wear a bolt, and the pop-up and a notification say so once. "Tell both" on the card sends each session a heads-up through its inbox, naming the other session and the file, so it re-reads it before changing it again. Only the path of each edited file is noted, in memory, and the same path means the same file, so two git worktrees of a repo never clash.
- **Calling for you** (decision 55). A session calls for you when it starts needing you, or finishes or fails a turn, however short, and it glows on the board until you read it, or until it gets going again. Opening its story reads it, and so does having it open in front of you when it calls, the open envelope that shows on its row on hover, and the pop-up's buttons. Reading clears only that call: the next one glows again. The page's title counts the sessions you haven't read, which the app shows as a red badge on its taskbar button, or on its Dock icon on a Mac. ✓ is always there: it takes the session off the board until it does something new, with no question asked, and it stays under "Earlier conversations". When you last read each session is kept in `mira.db`. A row calling for you says how long it has waited, as in "Your turn · 12 min", and "Next ▸" at the top, or Alt+N anywhere in Mira, the terminal included, opens the next session calling for you: one that needs you first, then the one that has waited longest (decision 57).
- **The board down the left** starts with prompts waiting for an answer, then lists every project, busiest first, with its sessions: status, last tool, how long ago and estimated cost, plus each project's recent commits. Click a session to fly to its mirling and open its story; click a project's name to fly to its section, and a section's name on the island to find the project on the left. Under each project, "Earlier conversations" unfolds the ones Claude Code still keeps, newest first, with their dates and costs; open one to read its story, and carry it on with Terminal or Continue in VS Code (decision 40). "☰ Sessions" folds it away for more island, and it starts folded on narrow screens.
- **Prompts.** While the page is open and on screen with "Answer prompts here" ticked, permission prompts wait for up to 60 seconds before the terminal asks. Answer them on the left or in the story. "Needs you" flies to the next mirling waiting.
- **Starting a session.** "+ New" on a project opens a new Claude Code chat in its VS Code window, with a prompt you type in Mira already in the box; you send it from VS Code (decision 29).
- **Renaming and removing.** A project's ⋯ menu has Rename and Remove, each session has ✎ on hover to rename it, and the story has Rename and Remove for its session. A session's name is saved where Claude Code keeps it, so VS Code and `claude --resume` show it too, and a session renamed in VS Code shows its new name here within a few seconds (decision 37). Project names and removals are kept in `mira.db`; a removed project or session comes back once something happens in it again, and ended sessions leave on their own after five minutes (decision 30).

**The story** shows every turn with its prompt, replies and tool calls, the subagents it started, and tokens and estimated cost for each turn and the whole session. Replies are rendered from Markdown by [web/markdown.js](web/markdown.js), which escapes all text first, so HTML in a reply shows as text; links open only for http(s), and links to repo files show as their names. The latest turn starts unfolded and the story follows the session live, and closing it zooms back out to the whole island, centred. "Continue in VS Code" at the top opens the conversation in Claude Code's chat panel, in the VS Code window whose workspace holds the session's folder, or in a new window on that folder. While a session is live, the box at the foot of its story sends it a message, wherever it runs, VS Code included: Enter sends, and Shift+Enter starts a new line (decision 46). It arrives in the session as a message from Mira, starting a turn if the session was waiting or read between tool calls if it was working, and the reply comes into the story, where your message shows as From Mira. Claude treats it as a request from another of your sessions, so it can't approve a permission prompt or change settings for you. The box needs the hooks below to pass on each session's inbox. When the session runs in Mira's own terminal and sits at its prompt, your turn, failed or waiting on its own work, the message is typed into the terminal instead, exactly as if you'd typed it there, so it arrives as yours; while it works, or asks something there that Enter would answer, it goes to the inbox as before (decision 57). The box says which way it will go. For a session in VS Code, "Paste in VS Code" beside Send copies your message and opens the conversation in its VS Code window, for Ctrl+V and Enter there, when it has to come from you, say to merge or push. Claude Code won't type into a conversation that's open in VS Code, and nothing can type into a window behind others, so pasting it yourself is as close as it gets. "Terminal" switches the story to a terminal running `claude --resume` in the session's folder, so you can carry the conversation on right there (decision 36). It keeps running if you close the story, and picks up where it was when you open it again: clicking a session whose terminal is running, on the left or on the island, opens straight onto the terminal. Stop ends it. Escape inside the terminal goes to Claude Code, not the page. It looks like my Windows Terminal: Cascadia Code, semi-light, 8 point, with cells 1.2 times the font size high and 0.6 wide. A− and A+ change the text size a point at a time, remembered in that browser. If the session is open in VS Code or another terminal, close it there first. Terminals run in the terminal host, a process of their own (decision 38), so restarting the hub, or the hub crashing, leaves them running: the page says it's reconnecting and carries on where it was a moment later. `npm run hub:stop` ends them, and the host ends itself once nothing has run in it for a minute. It logs to `~/.mira/terminals.log`. A link to the page with `#session=<id>` opens that session's story. Titles and stories are read from the transcripts when needed, and never stored.

On startup it rebuilds today's picture from stored events, reads recent Claude Code transcripts to find sessions that ran while it was stopped, and stores the token counts of turns that ended in the last day. Everything it keeps is in `~/.mira`:

| Path | What |
|---|---|
| `mira.db` | Events for 90 days, and every per-turn usage event, in SQLite (decisions 17, 23 and 32) |
| `recordings/` | Payload shapes, as the step 0 recorder wrote them, while `recordShapes` is on |
| `config.json` | Optional settings, below |
| `hub.log`, `hub.pid` | The log and process ID of a hub running in the background |
| `terminals.json`, `terminals.log` | The terminal host's pipe and secret, and its log (decision 38) |
| `inboxes.json` | Each running Claude Code session's inbox and token, for messages from the story (decision 46) |
| `update.json`, `update.log` | How the last update went, and the updater's log (decision 60) |

## Settings

`~/.mira/config.json` is optional. Every field has a default:

```json
{
  "port": 4711,
  "systems": { "acme-*": "Acme", "shop-web*": "Shop Web" },
  "mirlingNames": "cute",
  "permissionWaitSeconds": 60,
  "quickReplies": ["Go ahead", "Commit", "Commit and push"],
  "activeHours": 2,
  "recordShapes": true,
  "keepDays": 90,
  "checkForUpdates": true,
  "quiet": { "workingMinutes": 60, "idleHours": 12 },
  "prices": { "claude-opus-5-5": { "input": 4, "output": 20, "cacheRead": 0.2 } }
}
```

- `systems` renames or groups sections by repo folder name; Rename in Mira only changes the name shown (decision 30). A key is a folder name, or a pattern where `*` stands for anything, matched without case: `"acme-*": "Acme"` makes every acme repo one group. An exact name wins over a pattern, and patterns are tried in the order written. A group takes in its repos' earlier events, token counts and buildings too, starts from the arrangement of the repo you arranged most until you arrange the group, and labels each session with its repo; a new session in a group asks which repo (decision 47). Restart the hub after changing it. Taking a repo out of a group applies to what happens next: events it stored under the group stay there until they age out. Git worktrees join their main repo's section on their own, labelled with the worktree's folder name, so they need no entry here.
- `mirlingNames` picks the names mirlings get: `cute` (Pip, Mochi, Biscuit…) or `stars` (Vega, Altair, Rigel…). Each session keeps its seat, so switching renames every mirling at once, after a hub restart (decision 48).
- `permissionWaitSeconds` is how long a prompt waits for Mira while Mira is open. Keep it below the `PermissionRequest` hook's timeout, which is 65 seconds.
- `quickReplies` are the one-click replies on the app's pop-up, up to six, each up to 200 characters (decision 57). Restart the app after changing them.
- `activeHours` is how recent a transcript must be for its session to count as running at startup.
- `keepDays` is how many days of events to keep; 0 keeps everything. Per-turn token counts are always kept (decision 32).
- `checkForUpdates` fetches from the repo Mira was cloned from every six hours, to see whether it has an update (decision 60). Off, Mira still says where it stands against what was fetched before, and "Check now" in Settings still fetches.
- `quiet` is how long a session with no events stays in view: one still working, and any other. One waiting on a prompt always stays (decision 33).
- `prices` overrides or adds model prices for cost estimates, in US dollars per million tokens. Cache writes default to 1.25 times input for five minutes and twice input for an hour; set `cacheWrite5m` or `cacheWrite1h` to change them. The built-in table, in [src/pricing.ts](src/pricing.ts), holds Anthropic's first-party API prices as of October 2026. On a subscription these are only a measure of use, not a bill.

## Claude Code hooks

These go in `~/.claude/settings.json` under `"hooks"`. Watch-only hooks run `curl` in the background and fail silently when the hub is down (decision 20). `SessionEnd` runs in the foreground, so it isn't cut off as the session exits. Permission prompts get a direct HTTP hook (decision 18). The two `X-Mira-Inbox` headers pass on the session's inbox, which Claude Code gives its hooks as `CLAUDE_CODE_MESSAGING_SOCKET` and `CLAUDE_CODE_MESSAGING_TOKEN`, so Mira can send it messages (decision 46); without them everything else works, and the story has no message box.

```json
{
  "PreToolUse": [{ "hooks": [{ "type": "command", "async": true, "timeout": 10, "command": "curl -s -m 5 -X POST -H 'Content-Type: application/json' -H \"X-Mira-At: $(date +%s%3N)\" -H \"X-Mira-Inbox: $CLAUDE_CODE_MESSAGING_SOCKET\" -H \"X-Mira-Inbox-Token: $CLAUDE_CODE_MESSAGING_TOKEN\" --data-binary @- http://127.0.0.1:4711/ingest/claude-code > /dev/null 2>&1 || true" }] }],
  "SessionEnd": [{ "hooks": [{ "type": "command", "timeout": 5, "command": "curl -s -m 2 -X POST -H 'Content-Type: application/json' -H \"X-Mira-At: $(date +%s%3N)\" --data-binary @- http://127.0.0.1:4711/ingest/claude-code > /dev/null 2>&1 || true" }] }],
  "PermissionRequest": [{ "hooks": [{ "type": "http", "url": "http://127.0.0.1:4711/hooks/permission", "timeout": 65 }] }]
}
```

On a Mac, `date` can't print milliseconds, so use `$(perl -MTime::HiRes=time -e 'printf q(%d), time*1000')` in place of `$(date +%s%3N)`. On Linux, and on Windows, where Claude Code runs hooks with Git Bash, the lines work as they are.

The `PreToolUse` entry is repeated for `SessionStart`, `UserPromptSubmit`, `Stop`, `StopFailure`, `PostToolUse`, `PostToolUseFailure`, `PermissionDenied`, `SubagentStart`, `SubagentStop`, `Notification` and `CwdChanged`. `SessionEnd` needs no inbox headers: Claude Code closes the inbox before that hook runs, and the hub forgets it then.

| `POST /hooks/permission` | Claude Code permission prompts, held for an answer while Mira is open |
| `GET /api/sessions` | Live sessions and prompts waiting for an answer. Each session carries its mirling's `name` (decision 48), and `clashes`, `[{ file, with }]`, when it and another live session both edited a file in the last hour (decision 58). |
| `GET /api/sessions/:id/terminal` | Whether a session can have a terminal, and whether one is running. A WebSocket at the same address carries it: output down, keystrokes and size up. |

| `GET /api/sessions/:id/editor` | The VS Code window to continue a session in: `{ link, name }`, where `link` brings that window forward |
| `POST /api/sessions/:id/editor` | Opens the session in that window's Claude Code chat, a moment later |
| `POST /api/sessions/:id/read` | Marks what a session called you for as read. Sessions calling for you that you haven't read, needing you or with a turn that ended or failed since, have `unread: true` in `/api/sessions` (decision 55). |
| `POST /api/sessions/:id/message` | `{ "text" }`, up to 20,000 characters: sends a running session a message through its inbox (decision 46), or types it into the session's terminal in Mira while it sits at its prompt there (decision 57). `{ "via": "inbox" }` or `{ "via": "terminal" }` once it's handed over; 409 with the reason when it can't be. Sessions it can reach have `canMessage: true` in `/api/sessions`. |
| `POST /api/clashes/tell` | `{ "sessions": [one, other] }`: tells two sessions editing the same file about each other, through their inboxes (decision 58). `{ told }`, or 409 once they no longer clash. |
| `GET /api/layouts` | How each project's section is arranged in build mode, by project (decisions 39 and 44) |
| `PUT /api/layouts/:system` | A project's layout: `{ ground, placed, removed, moved, styles }`, places counted from its corner: its own ground from `1,1` to `8,8`, its shore at `0` and `9`, and the coast and streams around it from `-3` to `12`. Buildings move only on its own ground. An empty one forgets it. |
| `GET /api/systems/:name/history` | The project's earlier conversations, newest first, leaving out those on the board: `{ sessions: [{ id, title, lastAt, cwd, usage }], more }`. `?limit=20` and `?before=<lastAt>` page through them. Read from the sources when asked (decision 40). |
| `GET /api/systems/:name/start` | The project's folder and its VS Code window: `{ link, name, folder }`. A group of repos adds `choices`, one of these for each repo, the one used last first (decision 47). |
| `POST /api/systems/:name/start` | `{ "prompt", "folder" }`: opens a new Claude Code chat in that window, a moment later, with the prompt typed in. Up to 1,500 characters. `folder` picks one of a group's `choices`, and defaults to the first. |
| `GET /api/events?limit=100` | The most recent events |
| `GET /api/update` | Where Mira's own copy stands against its upstream: `{ state, running, upstream, behind, changes, packages, reason, checkedAt, updating, last }`, where `state` is `current`, `available`, `blocked` (new commits it leaves for you to pull, and why) or `unknown` (decision 60) |
| `POST /api/update/check` | Fetches from the upstream and looks again; the same answer |
| `POST /api/update` | `{ "app" }`, the app's process if the app asks: hands the update to the updater, which waits for the hub, and the app, to close, takes it and starts them again. 202 as it starts, or 409 with the reason it can't. |
| `GET /api/footprint` | What the hub and the terminal host cost the machine: `{ hub: { cpu, memory }, terminals: { running, usage } }`, where `cpu` is the share of the whole machine since the last ask and `memory` is in bytes, and `terminals` is null while no host runs (decision 61) |
| `GET /api/stream` | Live updates as Server-Sent Events, Mira's update among them. Add `?visible=0` for a viewer that isn't on screen. |
| `POST /api/presence` | `{ "viewer", "visible" }`: whether a viewer is on screen |
| `POST /api/prompts/:id` | `{ "decision": "allow" }`, `"deny"`, or `"terminal"` to hand the prompt back to the terminal at once |

## Adding a source

Each source is an adapter (decision 22), defined in [src/sources.ts](src/sources.ts). Every piece is optional: `ingest` turns what the source posts to `/ingest/<id>` into an event, `discover` finds its sessions at startup, `catchUp` fills in what was missed while the hub was stopped, `followUp` adds events that follow from one just recorded, `title` names a session, `story` tells it for the panel, `canMessage` and `message` send a running session my message, and `edits` lists the files its sessions edited lately, by path, so the hub can spot two sessions at the same file, whichever source each is from. Claude Code's adapter is [src/claude-code/source.ts](src/claude-code/source.ts). To add an agent, write its adapter, add it to the list in [src/main.ts](src/main.ts), and point the agent's hooks at `/ingest/<id>`.

## The browser side

[web/index.html](web/index.html) is the page. The live connection, the story panel, dialogs and styles are in [web/shared/](web/shared/), and the board down the left is [web/sky/sidebar.ts](web/sky/sidebar.ts). The sky's code is in [web/sky/](web/sky/): the island layout (`world.ts`), the scene (`scene.ts`) and the art. Browser code is TypeScript, which the hub sends with its types stripped (decision 26), so there's still no build step; `npm run typecheck` checks it against the DOM and Phaser's types.

**Swapping in an art pack (decision 25).** Every picture the sky uses has a name in [web/sky/art.ts](web/sky/art.ts), and [web/sky/drawn-art.ts](web/sky/drawn-art.ts) draws them all in code. A pack replaces it with one module that implements the same `Art` interface: load the pack's atlas in `preload`, register its frames under the same names in `create`, give buildings their anchors, and pass it to the scene in [web/sky/main.ts](web/sky/main.ts).

## Safety

- It listens on `127.0.0.1` only. It refuses requests that carry another site's `Origin`, a browser's mark that they came from another site (`Sec-Fetch-Site`), or a different `Host`, so a web page can't inject events, answer a prompt or read a story.
- It stores events, never content: no prompts, tool input or output, or messages. The command a permission prompt shows is held in memory while it waits, and never stored. The path of each file a session edits is held in memory for an hour, to spot two sessions at the same file, and never stored; the edit itself is dropped. The last reply on a pop-up card is read from the transcript when the card goes up, and kept only on the card.
- Mira updates only its own copy, only by fast-forwarding to the upstream branch it already tracks, and only when the copy has no changes or commits of its own. Checking runs `git fetch` and never asks for a password: a check that would need one just fails.
- Stories are read from transcripts when asked for, and only from files under `~/.claude/projects`, whatever path a hook payload names.
- Renaming a Claude Code session is the one write into Claude Code's files: one `custom-title` line appended to that session's own transcript, which must be under `~/.claude/projects` and named by its UUID, and its `custom-title.json`, exactly as Claude Code writes them.
- A message from the story goes only to a session the hub knows, into the inbox its own hooks named, which must look like one of Claude Code's (a `cc-msg-` named pipe on Windows, a socket file elsewhere). The inbox's token is kept in memory and in `~/.mira/inboxes.json`, readable only by you, and forgotten when the session ends or can't be reached. Messages pass through the hub and are never stored.
- A terminal runs only the source's own resume command, for a session the hub knows, with an ID that must be a UUID; its WebSocket takes the same this-machine-only checks as every other request. The hub passes on only what a page may say about its terminal (keystrokes, its size, start and stop). The terminal host listens on a local pipe and drops any connection that doesn't open with its secret, which it keeps in `~/.mira/terminals.json`. What's typed into it is passed straight to the program. A reply from the pop-up or the story is typed in only while the session sits at its prompt, with control characters taken out, so it can't answer a question the program is asking.
- The only things the hub opens on the desktop are Claude Code's own links: a session it already knows, by an ID that must be a UUID, or a new chat in a project folder it found from its own records, with my prompt typed in but not sent (decision 29). Which workspace holds which folder is read from VS Code's record of its open windows (`Code/User/globalStorage/storage.json`) and the workspace files it names, and never written.

**Continuing in VS Code, the first time.** The browser asks whether Mira may open VS Code; tick "Always allow". VS Code then asks whether to open the workspace from an outside link; tick "Allow opening local paths without asking". Until both are ticked, the conversation may open in whichever VS Code window was used last; clicking again puts it right.
